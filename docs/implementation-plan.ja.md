# 実装計画と評価方法

本書の完了条件は開発の到達点を定義する。新規な物理的結果の発見を、実装の完了と同一視しない。基本構成は[アーキテクチャ](architecture.ja.md)、数式の規約は[物理検証仕様](verification.ja.md)に従う。

## 1. 実装順序

| 段階 | 実装内容 | 完了を判定する具体的な条件 |
| --- | --- | --- |
| 1. 物理計算の最小実装 | Pythonパッケージ、式と模型の型、SU(2)のカレント、曲率、検証記録 | LLMなしで主カイラル模型の既知接続について両向きの式を確認できる |
| 2. 不十分な候補の検出 | 零接続、Maurer–Cartan恒等式しか含まない接続、方程式の欠落、特異な分母 | 数値的平坦性だけで合格せず、具体的な欠落と適用条件を返す |
| 3. 候補生成ツール | 係数方程式の構築と求解、PyTorchによる係数最適化、厳密な式の復元 | LLMなしで同じansatzを記号計算と数値最適化で探索し、同じ検証器へ渡せる。未復元の候補は未解決のまま残る |
| 4. 実行管理 | LangGraph、SQLite、ジョブ、予算、mock/replay、CLI | 求解後・記録前などで中断させても整合した状態に復旧できる。機械学習ジョブも予算に含める |
| 5. LLM接続とMCP | LiteLLM、設定プロファイル、操作の型検査、MCPラッパー | OpenAI・Anthropic・ローカルへのtool call往復を同じ操作schemaで比較できる |
| 6. 既知模型の探索 | 候補修正、球面の座標表示、ニューラルネットワークによる係数関数の学習の接続 | 正解接続を入力に含めず探索を記録する。学習した関数も厳密な式の復元と独立検証を経て扱う |
| 7. 結合定数の条件探索 | 結合した主カイラル模型、結合定数も含む最適化、分岐、既知構成との照合 | 特殊な分岐を失わず、成立条件と未解決領域を区別した報告を作れる |

最初に着手する差分は段階1と2とする。Lie代数の小さな厳密計算、既知の接続、意図的に不十分な接続を一つずつ揃える。エージェントを接続する前に検証器の誤判定を減らす。

Pythonからの直接呼出しを先に実装する。MCPは同じ関数を公開し、既存のエージェントから操作を試せるようにする。LangGraphによる探索の成否に関係なく、物理計算ライブラリを利用できる構成を保つ。

段階3で機械学習による候補生成の入出力を実装し、段階6で係数を関数として学習する方法へ広げる。有限個の係数の数値最適化と、ニューラルネットワークの学習は別々に評価する。LLMの追加学習はこの実装順序の前提にしない。詳細は[候補探索の仕様](ml-search.ja.md)に従う。

## 2. 最小の受入問題

表で用いる $`\mathcal E_1,\mathcal E_2`$ はスペクトルパラメータ $`z`$ に依存しない独立な方程式の左辺、 $`F(z)`$ は検査対象の残差とする。

| 問題 | 期待する結果 | 検出したい誤り |
| --- | --- | --- |
| SU(2)の主カイラル模型と既知の有理型接続 | 運動方程式を回収 | 正しい接続の取りこぼし |
| 同じ模型と零接続 | 前向きには平坦、方程式の回収は不成立 | 平坦なら可積分とする誤判定 |
| 同じ模型とMaurer–Cartan接続 | 運動方程式を含まないと診断 | 恒等式と運動方程式の混同 |
| 2つの独立な場のうち片方だけを含む接続 | 残りの方程式を回収できない | 一部の運動だけを検査する誤り |
| $`F(z)=\mathcal E_1+z\mathcal E_2`$ という係数行列の単体例 | スペクトル展開から2式を回収 | 一点のrankで判定する誤り |
| 運動方程式で割り算した偽の恒等式 | 定義域違反として不採用 | 特異な係数による形式的な検証の通過 |
| 一般点では回収でき、特殊な結合定数で小行列式が消える例 | 条件付き結果と別分岐を記録 | 一般点の結果の無条件な拡張 |
| 座標表示を持つ球面のシグマ模型 | 座標領域と独立な2式を記録 | 拘束を持つ3成分を独立な3式と数える誤り |
| 求解器を意図的に時間切れにする | 未解決として終了または再計画 | 計算失敗を非可積分性とする誤り |
| 学習で小さい残差を得たが厳密な式を復元できない候補 | 数値候補として保存し、未解決にする | 学習損失を恒等式の証明とする誤り |
| 数値係数の丸めで曲率恒等式が崩れる候補 | 復元後の非零残差を報告する | 丸めた式を無検証で採用する誤り |
| PyTorch未導入または機械学習ツール無効の設定 | 記号計算は動作し、機械学習操作は選択肢に出ない | 任意依存が基本機能を壊す誤り |

この表の単体例を評価データにする場合も、方程式と残差の定義を個々の入力に含める。

## 3. LLM接続の受入条件

各プロファイルについて、簡単な登録済みツールを呼ぶ、結果を返す、次の操作を型付きで受け取る、という往復を行う。接続確認だけでは物理能力の評価にならない。

| 検査 | 受入条件 |
| --- | --- |
| モデル切り替え | 設定のプロファイルを変更しても、物理計算とLangGraphのコードを変更しない |
| LiteLLMの変換 | tool-call ID、引数、tool result、必要なメッセージ情報が往復後も保存される |
| 対応外パラメータ | 黙って削除せず、設定エラーとして返す |
| 壊れたJSON・余分な引数 | Pydanticで拒否し、修正回数にも上限を付ける |
| 応答の打切り・拒否 | tool callが完結していなければ実行せず、状態を保存する |
| 再試行 | LiteLLMと外側のループの二重再試行を避け、費用と回数を一箇所で計上する |
| 評価中のモデル | fallbackを無効にし、要求したモデルと返却されたモデルを記録する |
| mock/replay | ネットワークとAPIキーなしで実行できる |

本設計の作成時点では、課金を伴うLLM呼出しは実行していない。モデルのAPI仕様の確認と、このプロジェクトの接続試験の完了を区別する。

## 4. 比較実験

| 方法 | 同じにする部分 | 調べること |
| --- | --- | --- |
| 固定順のansatz列挙＋記号計算 | 入力、候補クラス、求解器、資源上限 | LLMなしで回収できる範囲 |
| ランダムな候補選択＋同じ記号計算 | 候補クラス、ツール、資源上限 | 適応的な選択の効果 |
| 固定ansatz＋係数の数値最適化 | 入力、候補クラス、最終検証器、総予算 | 記号的求解に対する候補生成能力と復元の成功率 |
| 固定手順＋ニューラルネットワークによる候補生成 | 入力、関数クラス、最終検証器、総予算 | LLMを使わない機械学習の効果 |
| LLMによる探索で機械学習ツールを有効／無効にする | LLM、初期入力、最終検証器、総予算 | 機械学習ツールを使えることの効果 |
| LLMによる1回の提案＋検証 | 入力、最終検証器 | 知識の再生だけで解ける範囲 |
| LLMによる反復探索＋検証結果の返却 | 同じ最終検証器、総予算 | 失敗の診断を受けて修正する効果 |
| 反復探索からrank情報だけを除いた実験 | 最終検証器は変更しない | 欠けた方程式の情報の有用性 |
| 別のLLM・ローカルモデル | 問題とツールの版、評価手順 | モデル能力と計算費用の差 |

比較では、同じ数理計算予算の比較と、同じAPI費用上限の比較を分ける。候補数、求解に使ったCPU時間、学習に使ったGPU時間と機種、総実行時間、LLMの入出力トークン数、費用を併記する。学習の再試行と厳密な式の復元も集計する。高価なモデルを使った結果を、無制限の計算量で安価なモデルに対する優位としない。

主要指標は、独立検証を通った候補を得た問題の割合、不十分な候補を採用した割合、条件分岐の取りこぼし、最初の検証済み候補までの計算費用とする。既知の模型の正しい接続を回収する課題では、検証器の正しさを先に別の受入問題で測る。

既知模型の評価は、資料を検索せずに解く条件と、版を固定した参照資料を与える条件を区別する。前者でも基盤モデルの事前学習への混入を排除できたとは主張しない。新規発見を主張する場合には、未公表の対象、同値変換、既知の構成との関係を別途調べる。

追加学習を行う場合、同じ模型の座標変換・基底変換・パラメータの置換で作った例を訓練用と評価用へ分散させない。同値な例を一つのグループにまとめ、模型の族ごとに分割する。保存する操作履歴には、人間が修正した箇所と検証範囲を付ける。

## 5. 実装と研究の到達点

開発の最初の完了条件は、既知の主カイラル模型で候補提出から独立検証までを実行し、同じ実行を中断・再開・replayできることである。これは物理の新規性を示す成果ではない。

方法論の成果を評価する段階では、固定手順と同じ予算で比較し、どの失敗を検証結果に基づく修正で解消できたかを示す。単にLangGraphと記号計算を接続したことを新規性の中心に置かない。

理論物理の成果を目指す段階では、既知構成と同値でない模型・変形、未解決だった結合定数の条件、または仮定を明示した解析的な障害を対象にする。対象の選定には別の文献調査が必要であり、現時点で特定の未探索模型の新規性を確定したとはしない。

## 6. 今回の設計に対する確認

設計中に、主カイラル模型の恒等式 $`(1-z^2)F=\mathcal M-z\mathcal E`$ をSymPyで独立に展開し、差が厳密に零になることを確認した。スペクトル依存 $`(1,z)`$ のrankと、係数を分離した後のrankの差も確認した。

これは数式の規約と検査方針の確認であり、汎用の運動方程式導出、LangGraphの再開、LiteLLM接続を実装・検証したことを意味しない。
