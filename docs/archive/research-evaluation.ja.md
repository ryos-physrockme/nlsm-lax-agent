# 物理探索エージェントの論文評価と設計の点検

調査日：2026年9月9日。対象は `ryos-physrockme/nlsm-lax-agent` の設計コミット `458ea2f73f8ece78cf67b68bd7b27b346d00e0b7` である。

本書は、情報系と物理分野の先行論文・査読指針を参照して、2次元非線形シグマ模型のLax接続探索を研究として評価する方法を検討する。大規模言語モデルを以下ではLLMと略記する。対象コミットには設計文書と設定例だけがあり、探索器、検証器、評価問題集は未実装である。設計に項目が存在することと、実験で有用性が示されたことを区別する。

現在の設計は、物理的な判定の範囲、ツールの独立性、予算・履歴の管理を具体化している。一方、論文の結論を支える比較結果や物理的成果はまだない。特に、評価用模型の固定、汎用エージェントとの比較、反復実験の集計、人間の介入を含む実行記録を補う必要がある。

## 5. 物理論文に向けた評価計画案

この節の課題数と反復数は、費用を見積もるための開始案であり、掲載論文から得た合格基準ではない。開発用の試行で実行時間を測り、最終評価に着手する前に対象・回数・資源上限・主張を固定する。

### 5.1 検証器の確認と探索の評価を分ける

まず、既知接続と意図的に不十分な接続を用いて、検証器をLLMなしで検査する。この問題群は探索性能の得点には混ぜない。生成器と検証器で同じ誤りを共有しないよう、代表例について独立した導出・別実装も使う。記号計算による検証を、証明支援系による形式証明と同一視しない。

探索の最終評価は、対応済みの数族から12〜20課題、確率的な方法は課題ごとに5実行を開始案とする。主カイラル模型、球面の模型、結合定数を持つ模型のうち、開発で答えや調整結果を参照した例は開発用に残す。具体的な評価模型と文献による正解はまだ選定していないため、この数だけで十分な多様性があるとは判定しない。

| 課題の種類 | 出力と採点 |
| --- | --- |
| 接続の回収 | 指定した模型・領域で、曲率恒等式と運動方程式の回収を確認できる候補を提出する |
| 不十分なansatzからの修正 | 事前に指定した不足を含む出発点から、許された探索範囲内で検証に合格する接続を得る。既知解は入力に含めない |
| 表示の変更 | 基底や局所座標の変更後にも、同じ物理的判定を得る。同値変換の例を独立な新模型として数えない |
| 結合定数の条件探索 | 一般点・特殊点の条件と回収範囲を返す。正解が既知の範囲では分岐の取りこぼしを測る |
| 不成立・未解決の扱い | 特定候補の反証、指定ansatz内の探索失敗、模型の非可積分性を区別する。非可積分性を採点する場合は独立な根拠を持つ問題だけを使う |

同じ物理模型の座標・基底・パラメータの置換から作った例は同じグループとして扱う。同族内の未使用例への適用と、調整に使わない模型の族への適用を区別する。後者を用意できない間は、未見の族への一般化を主張しない。

評価用の参照接続、期待する検証記録、採点用データは、探索エージェントの作業ディレクトリと参照資料から除外する。特に、ファイルを読めるコーディングエージェントに、正解入りのリポジトリ全体を渡さない。ツールの説明・使用例は全比較条件で事前に固定する。公開済み模型の知識が基盤モデルの学習に含まれる可能性は、模型名を伏せただけでは除けない。

### 5.2 最小限の比較条件

次の条件を、主張に応じて比較する。独立提案とは、前の候補の失敗や検証診断を次の提案に返さない生成方式を意味する。

| 比較条件 | 固定・共有する部分 | 調べる効果 |
| --- | --- | --- |
| 固定手順によるansatz列挙と記号求解 | 入力、許す接続、資源上限、最終検証器 | 従来の自動計算で到達できる範囲 |
| 同じLLMによる独立した複数候補の提案 | 総予算、候補生成後の求解・復元・最終検証 | 反復の利点が、単に多く提案することを超えるか |
| 汎用コーディングエージェント＋通常の記号計算環境 | 入力、探索範囲、数理計算の予算、最終採点 | 専用ツールを提供することの効果を測る対照 |
| 同じ汎用エージェント＋本ツール群 | 基盤モデル、プロンプトの共通部分、予算、最終採点 | 検証・探索ツールを外部エージェントで使う価値 |
| 組み込みLangGraphエージェント＋本ツール群 | 可能なら同じ基盤モデル、同じツール・予算・最終採点 | 組み込みの探索手順・状態管理を加える効果 |

汎用エージェントの主比較はCodexまたはClaude Codeの一つから始める。もう一つは外部利用の動作確認や、代表課題での追試に使える。基盤モデルと設定をそろえられない比較は、システム全体の比較として報告する。その結果からLangGraphやツールだけの因果的な効果を結論しない。

機械学習による探索性能も論文で主張する場合は、LLMを使わず固定ansatzを数値最適化する条件を追加する。既存のLax探索手法から変更した点は明記し、単純な係数最適化を、元論文の忠実な再現やニューラルネットワークの学習と呼ばない。機械学習ツールのない記号計算主体の研究なら、未実装の機械学習の効果を主張しない。

すべての条件で同じ、版を固定した最終検証器を使う。数理計算の総時間、利用可能な計算機、LLMの利用上限、候補数、停止条件を記録する。ツールを外す比較ではツール呼出し回数だけを等しくしても計算量はそろわないため、プロセス全体の実行時間・資源使用も測る。API費用は別軸で報告し、単一の費用指標ですべてを同等としない。

### 5.3 構成要素を変更する比較

最初は、主張に直結する二つを優先する。

1. 方程式の欠落やrankに関する診断を探索側へ返す条件と、合否だけを返す条件を比較する。最終検証器は共通とする。
2. 適応的な候補修正と、同じ予算による独立提案を比較する。

機械学習ツールが研究の中心に入る場合に、有効・無効の比較を追加する。候補の合格条件自体を弱めた実験を、探索方法の改善として報告しない。平坦性だけなら誤採用される接続の分析は、検証器の比較として別に行う。

### 5.4 指標と実行履歴

| 指標 | 定義・集計上の注意 |
| --- | --- |
| 検証済み候補を得た実行の割合 | 事前に宣言した判定に合格する候補を予算内で一つ以上得た実行数を、開始した全実行数で割る。数値残差の小ささだけは合格に含めない |
| 不十分な候補の採用件数 | エージェントが有効と結論したが、独立の最終検証で不合格となった候補を数える。判定保留と反証済みを分け、分母も示す |
| 人間の介入なしの達成 | 実行開始後に人間の数式修正・ansatz提案・ヒントを受けずに達成した件数。人間が修正した結果は別に示す |
| 結合定数の条件の回収 | 正解が既知の評価領域について、回収した条件と見落とした分岐を記録する。未知の族に対して網羅率を作らない |
| 計算資源と費用 | 最初の検証済み候補までと、失敗・再試行も含む全実行の両方を集計。CPU時間、GPU時間・機種、経過時間、トークン数、API費用を記録する |
| 失敗理由 | 不適切な候補クラス、係数求解の未完了、数値候補の式の復元失敗、方程式の不足、特異条件、実行上の失敗などを記録する |

課題ごとの成功回数と実行数、費用・時間の分布を示し、最良の一回だけを主結果にしない。複数回のうち一度でも成功した割合を併記する場合は、試行数と全試行の費用を付ける。時間切れやエラーは、探索成功率の分母から都合よく除外しない。外部障害を別集計する場合も、その規則と件数を残す。

少数例では、まず「5実行中何回」の生データを出す。信頼区間を付ける場合は、固定課題での実行変動と、別の模型へ広げたときの不確実性を区別し、再標本化の単位を明記する。座標変換した例や同じ模型の再試行を、独立な模型の標本として扱わない。数族しかない評価で、広い模型空間に対する有意な優越を主張しない。

人間が入力・模型・ansatzを設計した作業と、実行中の介入を分ける。後者には介入時刻、対象の式、変更内容、理由、作業時間を記録する。介入前の失敗を保存し、介入後は別の実行IDで継続する。人間の時間を測定していなければ、研究者の作業時間を削減したという定量的主張はしない。

## 6. 提供する結果と論文の主張

結果の再現には三つの段階がある。第一に、保存された最終候補をLLMなしで再検算できること。第二に、保存された操作・応答を使って計算を再実行できること。第三に、同じ条件でLLMを新たに動かしたときの成功率を測れることである。保存履歴の再生だけでは第三の再現性を示したことにはならない。

研究用の配布物には、模型・領域・ansatzの定義、プロンプトとツールの仕様、実行環境と版、全実行の一覧、候補と検証記録、集計コードを含める。新しく得た主要結果は、探索器の内部状態に依存せず読める導出として記述し、代表的な検算を添える。探索結果の最終採点は、探索中に変更できない環境で実行する。

| 最終的に示せた成果 | 支えられる主張 | 追加で必要な確認 |
| --- | --- | --- |
| 既知接続の回収と不十分な候補の検出 | 実装が指定された問題で動作する | これだけを論文の新規性の中心にはしない |
| 物理に固有の検証・診断が、共通条件で誤採用や探索費用を改善 | 可積分性解析に有用な計算方法・ツール群 | 既存検証・探索手法との違いと、開発用以外での効果 |
| 専用の反復手順が汎用エージェント＋同じツールを上回る | その課題範囲における探索手順の改善 | 基盤モデル・予算・入力の差を取り除いた比較 |
| 未知だった成立条件や接続を得る | 新しいLax構造・条件の導出 | 既知分類、ゲージ変換・座標変換等との照合、解析的な検算 |
| Hamiltonian可積分性や非可積分性を示す | 追加の物理的結論 | その主張に必要な保存量・括弧・拘束や解析的障害の証拠。現行の初期範囲を超える |

組み込みエージェントが汎用エージェントを上回らなくても、専用ツールの有用性が示せれば、その成果に合う論文を構成できる。反対に、フレームワークの接続と既知例の動作だけでは、物理研究としての実質的な進歩はまだ示されていない。

次の実装では検証器を優先し、同時に開発用問題と最終評価用問題の仕様を別々に作成する。物理的な研究成果を重視する段階では、有限パラメータの模型について、一般点と特殊な分岐を含む一つの解析を完結させる。新規性が確認できるまでは、これを未解決問題の解決とは呼ばない。
